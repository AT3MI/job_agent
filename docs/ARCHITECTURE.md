# Архитектура job agent

## Обзор

Вход: текст вакансии (`job.txt`) + резюме (`data/resume.txt`). Выход: готовое сопроводительное
письмо (`letter.txt`) и метаданные (токены, вызовы, retry, правки лингвиста).

Дизайн-принцип: **модель — содержание, код — форма.** Всё, что можно посчитать без LLM,
считается кодом; модель работает только там, где нужен язык.

## Поток данных

```text
data/resume.txt → extract_facts.py → data/allowed_facts.json

job.txt → generate_letter(job_text)
      ↓
STANDARD_PROMPT + generate_standard() → StandardOutput (JSON, strict schema)
      ↓
ensure_unique_block_format()          [канонический заголовок «По X — отдельно.»]
      ↓
validate_standard(output, job_text)   [ошибки → retry полей → повторный вызов]
      ↓
СЛОЙ-ЛИНГВИСТ (SKIP_LINGUIST=1 отключает), 1 вызов в дефолтном пути:
      check (LLM) → apply (код: инварианты + trigram-guard)
      [VERIFY_LINGUIST=1: доп. вызов верификации → откат плохих правок]
      → ensure_unique_block_format ещё раз → validate_standard
      → хуже, чем было? → откат к снапшоту
      ↓
assemble_letter(output, facts) → готовый текст + metadata
```

## Контракт выхода

`StandardOutput` (config/schemas.py) — Pydantic-схема, GigaChat вызывается с
`chat_parse(..., strict=True)`: модель физически не может вернуть лишний блок.

| Поле | Содержание |
|---|---|
| `intro` | кто я, что ищу (1–2 предложения) |
| `vacancy_interest` | почему вакансия интересна, конкретика после «где …» |
| `best_solution` | якорный проект подробно: проблема → решение → результат |
| `unique_block` | начинается с «По [главное требование] — отдельно.», 2–3 умения с подтверждениями |
| `projects` | остальные проекты кратко (name, problem, result, link) |
| `medtech_experience` | только если вакансия связана с медтехом/документацией |
| `why_you` | личная мотивация |
| `closing` | формат работы + статус + контакты дословно |

## Детерминированные гарантии

1. **Заголовок `unique_block`** — `ensure_unique_block_format()`: схлопывает задвоения
   («отдельно — отдельно» → «отдельно»), ставит тире, вставляет маркер, если его нет.
   Идемпотентен. Применяется до промпта лингвиста и после правок.
2. **`closing`** — `CONTACTS_TEMPLATE` (config/identity.py) собирается из `.env`
   (`COVER_PHONE`, `COVER_VK`, `COVER_NAME`) и подставляется в промпт; модель повторяет его
   дословно. Валидация (deterministic.py) проверяет наличие номера, ссылки, подписи и ровно
   одного формата работы; `detect_work_format()` определяет формат по тексту вакансии
   (офис > гибрид > удалёнка).
3. **Факты** — модель ограничена `allowed_facts.json` + текстом вакансии; дословный блок
   личных качеств вырезается из резюме по маркеру и вставляется мимо модели.
4. **Retry полей** — при ошибках валидации конкретные поля перегенерируются отдельными
   короткими вызовами (`SingleFieldOutput`, `ProjectsOutput`). Когда валидация чистая,
   retry стоит 0 вызовов — страховка, а не расход.

## Слой-лингвист (src/generation/linguist.py)

Поверх валидного письма — корректор формулировок. В коде нет лингвистических правил:
вся оценка качества — LLM; код гарантирует механизм.

### Протокол

1. **Check (1 вызов, единственный в дефолтном пути).** Модель видит все редактируемые поля
   (`intro`, `vacancy_interest`, `best_solution`, `unique_block`, `medtech_experience`,
   `why_you`, `projects[N].problem/.result`), возвращает `LinguisticVerdict` — закрытая
   таксономия `repetition / grammar / tautology / fragment`, дословный `quote`
   (промпт просит 10–200 симв., инвариант применения принимает 10–300)
   и `fixed` (исправленное полное предложение). Пустой список — валидный ответ.
2. **Apply (код).** Quote ищется посимвольно (нормализация тире/пробелов), замена ровно
   одного вхождения, поля-зачины не переписываются (заголовок `unique_block` заморожен кодом).
3. **[Verify (1 вызов, за флагом `VERIFY_LINGUIST=1`).]** Модель проверяет дифф «было/стало»;
   `ok=false` → правка откатывается (в обратном порядке). По умолчанию выключена: её роль
   несут инварианты применения + `validate_standard` + снапшот-откат.
4. **Метаданные.** `meta["linguistic"]`: calls, tokens, issues_reported, applied, rejected
   (с причинами), verify_mode, edits со статусами.

### Инварианты применения (`_reject_reason`)

| Инвариант | Причина отказа |
|---|---|
| длина quote 10–300 симв. | `quote_size` |
| заголовок unique_block | `frozen_header` |
| непустая правка | `empty_fixed` |
| числа совпадают | `digits_changed` |
| нет новых ссылок | `link_added` |
| нет контактов | `contact_added` |
| длина ≤ ~1.6× quote | `too_long` |
| нет 3-граммного повтора из других предложений поля | `ngram_overlap` |
| fixed не дословно пересказывает парное поле problem/result того же проекта | `ngram_overlap_cross` |

### Trigram-guard

Правка не должна дублировать 3+ подряд слов из ДРУГОГО предложения того же поля
(«запихивание» повтора на новое место). Сравниваются наборы 3-грамм `fixed` и предложений
поля; предложение, содержащее правку, исключено — минимальная правка законно сохраняет слова
своей фразы. Для полей `projects[N].problem/.result` правка дополнительно сверяется с
парным полем того же проекта (`ngram_overlap_cross`): тавтология «результат пересказывает
проблему» живёт между двумя полями и внутри поля не видна. Совпадение → отказ, текст
остаётся как был (консервативно). Это защита данных (в ряду инварианта чисел), не
лингвистическое правило. Флаги: `TRIGRAM_GUARD=0` — выключить, `MAX_NGRAM_OVERLAP` — порог
(по умолчанию 0). Дословный уровень: морфологические повторы («полному циклу» ↔ «полным
циклом») ловит промпт проверки, не guard.

### Уровни отката

1. отказ правки инвариантом (правка не применяется);
2. verify-верификатор (`VERIFY_LINGUIST=1`) — откат плохих правок;
3. снапшот-откат: после лингвиста письмо снова проходит `validate_standard`; хуже →
   полный откат к снапшоту;
4. `SKIP_LINGUIST=1` — слой целиком; git — уровень кода.

## Конфигурация

| Файл/переменная | Назначение |
|---|---|
| `.env` → `GIGACHAT_CREDENTIALS` | ключ GigaChat (не публикуется) |
| `.env` → `GIGACHAT_CA_BUNDLE_FILE` | CA-сертификат Минцифры |
| `.env` → `COVER_PHONE` / `COVER_VK` / `COVER_NAME` | контакты closing (config/identity.py) |
| `config/paths.py` | все пути от корня проекта |
| `client.py` → `TOKEN_BUDGET_PER_LETTER` | бюджет токенов на письмо (15000) |

## Запуск

```bash
python extract_facts.py       # резюме → факты (несколько вызовов API)
python main.py job.txt        # письмо + letter.txt + метаданные
python test_linguist.py       # 63 офлайн-проверки (stub-клиент, без API)
python -m compileall config src extract_facts.py
```
